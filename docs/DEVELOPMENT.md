# 开发约定

## 业务边界

学生不创建账号；教师与管理员使用 Django 用户。`role=teacher` 的有效登录用户预约自动批准，普通学生角色账号（仅供管理员特殊管理）仍走审批。`is_staff` 用于学院审批权限，`is_superuser` 用于全校资源与系统用户管理。

学生免账号身份是自填信息，不能自动证明学籍。学院限制不以免登录填写的“学院”文本授予权限；学生只看 `department=""` 的全校共享教室。需开放院内教室给学生时，应先设计可信身份核验，而不是将自填学院当授权凭据。

## 预约不变量

所有创建/审批/取消/导入必须调用 `booking.services`，先锁教室，再校验并更新记录。使用 MySQL InnoDB + READ COMMITTED。待审与已批准都占用 `[start_at, end_at)`，教学占用与普通申请同表参与冲突检测。课程导入按教室主键顺序取锁，并在一个事务中处理，任一错误整批回滚。

Django 后台预约表只读，禁止绕开事务服务直接保存。不要给预约添加普通 `ModelAdmin.save_model`，也不要通过通用 API 直接修改状态。直接数据库写入不受应用事务锁协议保护，数据库账号只发给可信运维。

MySQL 的跨行时间重叠没有排除约束；因此只有遵守同一教室行锁协议的写入保证并发正确性。SQLite 不支持此锁协议，仅用于本地界面/单用户验证。

## 时间与保留

界面为北京时间 `Asia/Shanghai`，数据库使用 Django 时区感知时间。预约同一天 07:00–22:00，未来 30 天；最长时长可通过环境变量设定，不支持跨夜/周期预约。数据最大保留 60 天，从创建时计算。测试使用相对日期，避免样例日期过期。

## 本地命令

见 README。代码变化若涉及模型，请增加迁移文件、运行相关测试与 MySQL 并发测试。保存清理步骤，不要把进程存活等同于下次任务自动启动。当前云任务已有隔离环境，使用现有 checkout，不创建额外 Git worktree。

## 部署依赖

主路径是 MySQL 8 + mysqlclient。可选 PostgreSQL 后端安装 `requirements-postgres.txt`；默认生产镜像仅安装 MySQL 驱动，若更换 PostgreSQL，需调整镜像依赖并独立执行测试。生产配置不接受默认开发密钥，不默认使用 SQLite。

代理环境构建可使用标准 Docker `HTTP_PROXY`/`HTTPS_PROXY` build args。若公司代理需要自签受信 CA，构建支持可选 BuildKit secret `build_ca`，仅为 pip 验证使用；不要禁用 TLS 校验。普通腾讯云构建无需此参数。系统包安装始终保留 APT 签名验证。
