# 预约信息最多一个月：执行口径

本系统将“一个月”解释为**固定上限 30 天**，从记录的 `created_at`（提交/导入时间）计算，不从审批、活动结束或最后修改时间重新计时。拒绝、取消、教学占用同样到期清理。

## 在线数据

- `RETENTION_DAYS` 可设为 2–30，超出 30 的配置会被限制到 30；生产模板设为 **21 天**，为备份过期留出空间。
- 所有用户查询、管理员列表、统计和时段冲突检查都排除到期记录，到期后本人验证授权立即失效。
- `retention` 容器每 60 秒分批物理删除过期预约及级联审计记录；预约中保存的借用人姓名、学号/工号、学院、联系方式及密码哈希随预约删除。
- 清理同时删除过期登录会话和一天前的限流计数。会话最长 8 小时，本次预约密码永不写入会话，会话内只记录该笔预约 ID、凭据版本和 15 分钟授权期限。
- 删除以数据库逻辑删除/物理行删除语义为准，不声称立即擦除存储介质空闲页。对存储残留的安全擦除需要云平台加密与密钥生命周期策略。
- 清理进程故障时，到期记录仍不对用户提供；物理删除会延迟，所以必须监控该容器，不能仅保存清理命令就当作保留策略已落实。

管理员账号和教室基础资料不属于预约记录，不随预约自动删除。账号停用或离职由学校管理员处理；为避免损坏未到期记录，应先停用账号，而非强制删除有历史关联的账号。

## 备份、二进制日志和云快照

仅删除在线数据，无法确保旧备份中没有学生信息。因此默认在线 21 天，并要求：

1. 新数据库的自动备份、手工备份、二进制日志、PITR 恢复日志、异地副本及服务器快照，**最长保留 7 天**。在线 21 天 + 最后备份 7 天 < 30 天，预留清理与备份调度余量。
2. 如学校选择在线保留 30 天，应避免持久化包含预约个人信息的历史备份，或采用能在第 30 天同步删除对应个人信息的独立策略。不能承诺“在线 30 天再加任意备份”仍然符合一个月上限。
3. 使用既有腾讯云实例时，其备份可能覆盖主站和预约库。如果无法在不影响主站要求的情况下保证该上限，请为预约创建**独立数据库实例**，或使用本仓库可选的独立 MySQL 容器及适当快照策略。独立账号不等于独立备份策略。
4. 本地 MySQL 示例关闭 binlog，未自动创建任何备份任务。需要恢复能力时，应由运维增加加密备份并设置不超过 7 天的过期删除和恢复演练。不能将“未配置备份”理解为已经具备灾难恢复。
5. 不在请求日志中记录表单、预约密码、姓名、学号；不把数据库导出提交 GitHub 或打进交付 ZIP。导出统计默认只包含聚合数字，不含个人信息。
6. 从备份恢复后，先保持维护状态，执行 `python manage.py purge_expired` 成功后才重新开放应用；验证过期预约仍无法查询或修改。

## 排查与验证

```bash
docker compose ps retention
docker compose exec retention python deploy/check_retention.py
docker compose run --rm web python manage.py purge_expired
```

应用测试覆盖过期记录不可查、预约及审计级联删除、过期会话清理。实际腾讯云备份、快照和日志期限需要在云控制台核对；源码无法读取或修改现有主站与数据库实例的备份策略。

## 学期课表配置

`TeachingRule` 保存的是正式教学计划（教室、课程、任课教师、学期周次与时段），不包含学生学号、联系方式或预约密码。它作为教学配置保持到学期结束后至多一个保留周期，由后台同步任务清除；不会因具体占用行清理而丢失一学期的计划。具体预约和教学占用行仍按创建时间清理。远期课程通过规则计算展示，不将学生预约延长保存。

## 使用日期与生命周期

默认提前借用窗口为 14 天，且不会超过保留期减一天，避免新预约在使用前到期。编辑既有记录不会刷新创建时间；如果新的使用日期已超出它剩余的保留期，需取消后重新创建一笔预约。旧环境请将 `.env` 改为 `RETENTION_DAYS=21`、`BOOKING_ADVANCE_DAYS=14`，并将相关备份/日志/快照期限改为不超过 7 天；旧的在线 45 天配置虽然会被代码限制为 30 天，但再叠加备份仍可能超出一个月总上限。
